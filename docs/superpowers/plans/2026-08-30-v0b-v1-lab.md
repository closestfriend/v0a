# V0B Core and V1-Lab Implementation Plan

> Execute in order. Stage 2 is gated on the Stage 1 acceptance executable and the existing V0A CTest suite both passing.

**Goal:** Add automatic monophonic correction to the verified V0A engine, then expose the exact same DSP classes in a minimal arm64 JUCE AU/VST3 for Ableton Live experimentation.

**Architecture:** `v0a_dsp` remains the single DSP library. Both the offline V0B renderer and the JUCE processor own a `PitchCorrectionEngine` from that library. The existing `CycleResampler` pointer/splice algorithm is preserved; only bounded, real-time-safe runtime configuration is added around its existing state.

**Toolchain:** C++20, CMake, local JUCE 7.0.12, CTest, Apple AU/VST3 bundles.

## Stage 1 — Minimum viable V0B core

### Task 1: Runtime-safe V0A control seam

**Files:** `tests/test_cycle_resampler.cpp`, `src/dsp/CycleResampler.{h,cpp}`

1. Add failing behavioral tests proving period/rate changes alter event direction and remain bounded, while invalid runtime values are rejected without mutating state.
2. Add a `noexcept` runtime setter using the existing algorithm and preallocated buffer.
3. Run the focused resampler test, then all existing V0A tests.

### Task 2: Pitch math, scale presets, and exact matrix semantics

**Files:** `tests/test_note_quantizer.cpp`, `src/dsp/PitchMath.h`, `src/dsp/NoteMatrix.{h,cpp}`, `src/dsp/NoteQuantizer.{h,cpp}`

1. Add failing literal boundary tests at F−49/F/F+49 cents for Target, Bypass, and Remove, plus the 49/51-cent midpoint test, no-target behavior, Key/Scale presets, and Custom-on-edit.
2. Implement fixed chromatic cells, nearest Target over bounded octaves, upward tie-breaking, and preset loading.
3. Run the focused test.

### Task 3: Retune controller with a true zero

**Files:** `tests/test_retune_controller.cpp`, `src/dsp/RetuneController.{h,cpp}`

1. Add failing tests proving Retune 0 replaces the ratio immediately and nonzero Retune follows the specified ratio-domain one-pole response.
2. Implement a no-allocation controller with no hidden minimum time constant.
3. Run the focused test.

### Task 4: Transparent reference period/F0 detector

**Files:** `tests/test_pitch_detector.cpp`, `src/dsp/PitchDetector.{h,cpp}`

1. Add failing tests for clean sine, saw/vowel-like harmonic content, silence/noise rejection, and an L-vs-2L case that would otherwise octave-mistrack.
2. Implement a preallocated, inspectable difference-family detector with energy-relative voiced gating, quadratic lag refinement, and explicit L/2L arbitration.
3. Run the focused test and retain detector metrics in the public result structure.

### Task 5: Shared automatic correction engine and CSV renderer

**Files:** `tests/test_pitch_correction_engine.cpp`, `src/dsp/PitchCorrectionEngine.{h,cpp}`, `src/app/AutoTuneRenderer.{h,cpp}`, `tools/v0b_renderer/main.cpp`, `CMakeLists.txt`

1. Add failing end-to-end tests proving voiced samples use the detected period/target/retune ratio, unvoiced samples select unity, and the resampler counters remain bounded.
2. Compose detector, quantizer, Retune controller, and the existing CycleResampler in one preallocated engine shared by all hosts.
3. Add an offline WAV renderer and required diagnostic CSV columns.
4. Run focused tests.

### Task 6: Decisive V0B acceptance gate

**Files:** `tests/test_v0b_acceptance.cpp`, `src/app/AcceptanceSignals.{h,cpp}`, `tools/v0b_acceptance/main.cpp`, `CMakeLists.txt`, `renders/v0b/*`

1. Add independent synthetic checks for sine glissando staircase/midpoints/Retune 0, harmonic glissando octave tracking/direction/bounds, vibrato flattening, voiced-unvoiced unity transitions, and 49/51-cent selection.
2. Render compact WAV/CSV evidence and fail the executable on violated metrics.
3. Run the acceptance executable and full V0A+V0B CTest suite, including sanitizer build.
4. Stop Stage 1 if any decisive check fails; do not begin forensic calibration.

## Stage 2 — V1-Lab JUCE build

### Task 7: Shared experimental controllers needed by the lab surface

**Files:** `tests/test_humanize_controller.cpp`, `src/dsp/HumanizeController.{h,cpp}`, shared config headers

1. Add failing tests discriminating multiplicative and additive Humanize at Retune 0.
2. Implement both explicitly experimental modes without changing the V0B default path.
3. Add bounded runtime config for interpolation, splice crossfade, F0 bounds, tracking epsilon, unvoiced mode, target hysteresis/confirmation defaults, and Retune domain where already supported.

### Task 8: JUCE processor using the shared engine

**Files:** `plugin/PluginProcessor.{h,cpp}`, `CMakeLists.txt`

1. Add the AU/VST3 target linked to `v0a_dsp`; do not duplicate DSP in plugin sources.
2. Allocate/prepare in `prepareToPlay`; process mono and duplicate to stereo without allocations, locks, I/O, logging, GUI work, or resizing in `processBlock`.
3. Use atomic parameter snapshots and atomic diagnostics.
4. Measure the fixed engine delay, call `setLatencySamples()`, and route bypass through the same delayed unity-rate path.

### Task 9: Minimal lab editor

**Files:** `plugin/PluginEditor.{h,cpp}`, optional small UI component files

1. Build a compact graphite/steel interface with one blue Target accent, normal controls, 12-key tri-state note matrix, diagnostic display, and collapsible developer panel.
2. Manual note edits set Scale to Custom and change the shared quantizer configuration.
3. Keep UI state off the audio thread and avoid decorative production polish.

### Task 10: Build, install, validate, and load

1. Configure/build arm64 AU and VST3 against the local JUCE tree.
2. Verify binary architectures and bundle contents.
3. Install to the user Audio Plug-Ins folders.
4. Run AU validation and practical VST3 checks.
5. Launch/scan in Ableton Live, instantiate if automation permits, confirm audio/parameters/note matrix, and inspect for obvious real-time failures.
6. Once automatic correction loads and runs in Ableton, stop and report artifacts, latency, defaults, and audition risks.
